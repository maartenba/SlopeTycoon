## Known issues / unverified

- All rendering (terrain/water/snow shaders, models, overlays, incident visuals) and all audio were never seen or heard by an agent (no WebGL / audio device); only logic is unit-tested.
- All FPS / GPU / memory numbers in a browser are unmeasured; `high` shadows are a no-op (nothing casts shadows); `low` quality look unverified.
- Funicular car: three stepped compartments, looks unverified on a real slope (docs/models.md).
- `GuestRenderer` CPU culling margin (12 %) may pop guests during fast camera pans.
- News / HUD / assistant layout may overlap at small widths; the assistant can overlap the debug panel when it is open (dev-only panel).
- Guests queueing / riding at save time become idle on load; attraction queues and overnight bookings are reset (docs/saves.md). A very fast tab close can lose the last autosave. Terrain is regenerated from the seed on load (~250 ms at 256).
- Loading a slot reloads the page (design decision).
- Tutorial progress and settings are stored in LocalStorage, not in save files.
- Balance: only seeds 1337 / 61 / 7 swept; the bot never adds lifts after the opening chain; arrivals limited by parking capacity in the starter resort (docs/balance.md, docs/marketing-pricing.md).
- Most streams end "dead" (pits / village exclusion), few reach a lake or the map edge; pistes could be painted over streams (reported open at Task 28; not re-verified).
- `NavWorld.terrainVersion` not wired in `main.ts` (learnings, Task 28 note); impact unverified.
- Both JS chunks exceed Vite's 500 kB warning (not split further).
- `muteMusicInMenus` audio setting is a placeholder (unused).
- Licence not chosen.
